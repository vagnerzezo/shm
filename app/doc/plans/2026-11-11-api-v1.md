# API v1 do SHM — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** API `/api/v1` em JSON, com login por token, para o cliente e o barbeiro usarem pelo app; perfil barbeiro; marcação sem corrida no site e no app.

**Architecture:** A regra de negócio sai das Server Actions para funções em `app/_lib/domain/`, que recebem dados simples e lançam `DomainError`. Server Actions e rotas HTTP (`app/api/v1/**/route.ts`) viram cascas finas em volta dessas funções. A sessão vale por cookie ou por `Authorization: Bearer`, na mesma tabela `sessions`, com o token guardado como hash.

**Tech Stack:** Next 16 (App Router, Route Handlers), TypeScript, Drizzle + `pg` (Neon), `node:test` via `tsx`, Postman CLI.

**Spec:** `app/doc/specs/2026-11-11-api-v1-design.md`

## Review Focus

1. **Corpo inválido** (JSON quebrado, array, campo com tipo errado): resposta `400 validation`, nunca `500`. → teste na Tarefa 1.
2. **Datas impossíveis ou intervalo ruim** (`2026-02-31`, `from > to`, mais de 31 dias) em `/availability` e `/barber/agenda`: `400`. → Tarefas 6 e 10.
3. **Token ruim** (lixo, expirado, de conta desativada, cabeçalho sem `Bearer`): `401`, sem derrubar a rota. → Tarefa 3.
4. **Id de reserva de outro cliente** em remarcar/cancelar: `404` (não confirma que existe). → Tarefa 7.
5. **Lista de itens estranha** em `POST /reservations` (vazia, item repetido, dois itens que se sobrepõem, mais de 10): `400`, nada gravado. → Tarefa 7.
